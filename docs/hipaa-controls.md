# HIPAA technical safeguards: controls matrix (45 CFR 164.312)

This maps each standard and implementation specification of the HIPAA Security Rule's
**technical safeguards** to the code, test or Terraform in this repo that addresses it, or
names it as the adopter's responsibility. It is what **HIPAA-ready** means here: the
technical controls a covered entity or business associate would expect from software that
handles ePHI, each with a test that fails if the control breaks.

It is **not** a statement of compliance. Compliance belongs to an organisation: a risk
analysis (164.308(a)(1)), policies and workforce training, business associate agreements
(with AWS, with the FHIR system's operator), contingency planning and backups, physical
safeguards (164.310) and breach notification. None of those can live in a repo. This repo
uses synthetic data only and has never held real ePHI.

**How to read it.** *R* is a required specification and *A* an addressable one (the
organisation assesses it, then implements it or documents an equivalent). *Status* is
`Addressed` (the technical control is here and tested), `Partly` (the repo covers part of
it; the rest is in the last column) or `Adopter` (nothing in this repo can meet it).
*Evidence* cites files, tests (`file::test`) and Terraform test runs (`file::run`).
`scripts/check_docs.py` (CI `test` job) fails if any cited file, test or run no longer
exists, if a specification is missing, or if an `Addressed` or `Partly` row cites no test.

## Outside 164.312, and never in this repo

- **Administrative safeguards (164.308):** risk analysis and management, a security official,
  workforce training and sanctions, access authorisation and review, incident procedures,
  contingency plan, evaluation, and business associate agreements.
- **Physical safeguards (164.310):** facility access, workstations, device and media controls.
  In the blueprint these are AWS's under its BAA, for HIPAA-eligible services only
  (`infra/aws/hipaa-services.json`).
- **Organisational, policy and documentation requirements (164.314, 164.316),** and the
  Privacy and Breach Notification Rules.

See also: [`threat-model.md`](threat-model.md) (what these controls defend against, and what
they do not), [`SECURITY.md`](../SECURITY.md), and the README's "Can I use it with real
patient data?".
